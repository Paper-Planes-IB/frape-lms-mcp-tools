# Аудит исходника

Дата: 3 октября 2026. Проверен upstream-коммит `b8ece3fe8d1a18353c0b35c953e5afb6b19f56cb`.
Прочитаны client.py, tools.py, server.py; дополнительно изучен db.py.

В этих трёх файлах не обнаружены eval/exec, запуск команд оболочки, встроенные API-секреты,
телеметрия или отправка учебного содержимого на сторонний адрес.
REST-запросы строятся относительно base_url. Однако upstream выбирает base_url из активного
SQLite-подключения раньше FRAPPE_URL, допускает смену подключения, хранит credentials в SQLite,
предлагает парольный вход и запускает веб-панель. Все инструменты записи регистрируются без ограничения.
Поэтому исходный сервер нельзя публиковать без доработки.

В форке:

- HTTP разрешает только read-only; список регистрации задаётся явно.
- HTTP-клиент блокирует записи и произвольные вызовы Frappe methods в read-only.
- Только API-токены из окружения; адрес — HTTPS origin из FRAPPE_URL; редиректы запрещены.
- Учётные данные не читаются из SQLite и не сохраняются в кеше.
- HTTP/SSE защищены Bearer-токеном; query-token выключен по умолчанию.
- Удалены из HTTP-режима веб-панель и выбор подключения.
- Имена документов кодируются в URL. Ошибки Frappe не возвращают тела ответов с внутренними данными.
- Доступ подкреплён отдельной сервисной ролью на стороне Frappe.

Границы проверки: это аудит названных модулей и изменённого пути исполнения, без полного аудита
Frappe, FastMCP и всех транзитивных зависимостей. В pyproject upstream указана MIT;
отдельного LICENSE в исходном репозитории нет. Клиентский контент и секреты в форк не включаются.
